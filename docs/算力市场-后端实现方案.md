## 二、数据库设计

### 2.1 方案选择：扩展现有 `sys_ecs` 表

**理由**：
- 现有 `sys_ecs` 已承载 GPU 资源核心字段，扩展比新建表更符合简单优先原则
- 管理系统已有基于 `sys_ecs` 的产品管理页面，复用可减少前端改造
- 订单、计费系统已关联 `sys_ecs`，避免外键重构

**决策**：在 `sys_ecs` 表中新增算力市场专用字段，通过 `productType` 区分不同产品线。

### 2.2 表结构变更（DDL）

```sql
-- 扩展 sys_ecs 表，新增算力市场字段

ALTER TABLE sys_ecs ADD COLUMN rentable_until DATE COMMENT '可租用截止日期' AFTER machine_uuid;
ALTER TABLE sys_ecs ADD COLUMN available_count INT DEFAULT 0 COMMENT '空闲GPU数量' AFTER rentable_until;
ALTER TABLE sys_ecs ADD COLUMN total_count INT DEFAULT 0 COMMENT 'GPU总量' AFTER available_count;
ALTER TABLE sys_ecs ADD COLUMN cache_optimized TINYINT(1) DEFAULT 0 COMMENT '是否缓存优化 0否 1是' AFTER total_count;
ALTER TABLE sys_ecs ADD COLUMN cpu_model_detail VARCHAR(128) COMMENT 'CPU型号全称' AFTER cache_optimized;
ALTER TABLE sys_ecs ADD COLUMN system_disk VARCHAR(32) COMMENT '系统盘' AFTER cpu_model_detail;
ALTER TABLE sys_ecs ADD COLUMN data_disk VARCHAR(32) COMMENT '数据盘' AFTER system_disk;
ALTER TABLE sys_ecs ADD COLUMN expandable VARCHAR(32) COMMENT '可扩容容量' AFTER data_disk;
ALTER TABLE sys_ecs ADD COLUMN gpu_driver VARCHAR(64) COMMENT 'GPU驱动版本' AFTER expandable;
ALTER TABLE sys_ecs ADD COLUMN cuda_version VARCHAR(32) COMMENT 'CUDA版本' AFTER gpu_driver;
ALTER TABLE sys_ecs ADD COLUMN discount_price DECIMAL(10,2) COMMENT '会员折扣价' AFTER three_year_price;
ALTER TABLE sys_ecs ADD COLUMN discount_rate VARCHAR(10) COMMENT '折扣率，如9.5' AFTER discount_price;
ALTER TABLE sys_ecs ADD COLUMN region_name VARCHAR(32) COMMENT '地区名称，如西北B区' AFTER regions_zones;
ALTER TABLE sys_ecs ADD COLUMN zone_type VARCHAR(32) COMMENT '专区类型，如V100专区' AFTER region_name;
ALTER TABLE sys_ecs ADD COLUMN status TINYINT(1) DEFAULT 1 COMMENT '状态 1上架 2下架' AFTER zone_type;

-- 新增索引
CREATE INDEX idx_region_name ON sys_ecs(region_name);
CREATE INDEX idx_zone_type ON sys_ecs(zone_type);
CREATE INDEX idx_gpu_model ON sys_ecs(gpu_model);
CREATE INDEX idx_status ON sys_ecs(status);
CREATE INDEX idx_product_type ON sys_ecs(product_type);
```

## 七、关键决策

### 决策 1：扩展现有表 vs 新建表
- **选择**：扩展 `sys_ecs`
- **理由**：已有订单/计费系统关联，减少改造成本

### 决策 2：管理端使用现有 ProTable 组件
- **选择**：复用 `ux-admin-main` 中现有的 `ProTable` 组件
- **理由**：保持代码一致性，减少重复开发

### 决策 3：地区/专区使用配置表
- **选择**：新建 `sys_gpu_zone` 和 `sys_gpu_region`
- **理由**：支持动态配置，管理端可维护，避免硬编码

### 决策 4：availableCount 实时性
- **选择**：数据库存储 + 定时任务同步
- **理由**：真正的实时需要对接底层云厂商 API，当前阶段使用定时同步（5分钟）
- **后续**：可接入消息队列实现准实时更新
