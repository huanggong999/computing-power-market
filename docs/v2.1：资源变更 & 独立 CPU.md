本批共 **13 个接口**（序号 64–76），为 **v2.1 纯新增能力**：独立模块、独立路由前缀、独立鉴权前置，与原 GPU 实例链路**互相独立**，可单独灰度上线，不影响任何既有接口行为。分两组：

+ **A. 用户端资源变更**（64–68）：公网带宽扩缩、磁盘扩容、CPU/内存扩缩、GPU 卡数同型号升配（1 → N，原地变配 + 镜像模式）。
+ **B. 独立 CPU 实例**（69–76）：购买「不加入集群」的纯 CPU 云主机，独立售卖通道。

### <font style="color:#2c3e50;">能力与边界（先看这张表）</font>
| **<font style="color:#2c3e50;">能力</font>** | **<font style="color:#2c3e50;">扩容</font>** | **<font style="color:#2c3e50;">缩容</font>** | **<font style="color:#2c3e50;">说明</font>** |
| --- | --- | --- | --- |
| 公网带宽 | 是 | 是 | 四项能力中唯一可双向调整的项（降低带宽可能造成丢包，业务侧自行评估） |
| 云盘（数据盘） | 是 | 否 | 云盘容量**物理不可缩**，请求缩容会被明确拒绝（不做静默降级） |
| 火山云（ECS）CPU / 内存 | 是 | 是 | 变更前**必须先停机**，改完由云端自动开机（也可指定目标规格 ID 升配） |
| 平台自建节点 CPU / 内存 | 是 | 否 | 节点资源不会实际回收，故不支持缩容（需降本请新建小规格实例后迁移） |
| GPU 卡数（同型号 1 → N） | 是 | 否 | **原地变配 + 镜像模式**：仅限火山云采购的 GPU 实例、且必须是**同一 GPU 型号**；改规格需停机，改完用同一镜像按新卡数重建 Pod（不重建镜像） |
| GPU 规格 ⇄ CPU 规格 | 否 | 否 | **不允许互相变更**：GPU 实例只能改磁盘 / CPU / 内存 / 同型号卡数；CPU 实例只能改磁盘 / CPU / 内存。跨规格族会被直接拒绝（`<font style="color:#333;">SpecCrossFamilyForbidden</font>`<br/> / `<font style="color:#333;">GpuModelChangeForbidden</font>`<br/>） |


<font style="color:#2c5282;background-color:#f0f7ff;">注意：</font>**<font style="color:#2c5282;background-color:#f0f7ff;">实例来源自动分流</font>**<font style="color:#2c5282;background-color:#f0f7ff;">：实例可能来自「平台自建节点」或「火山云采购」。接口按实例标签自动判定来源：火山采购的实例</font>**<font style="color:#2c5282;background-color:#f0f7ff;">去云端真实变配/扩盘</font>**<font style="color:#2c5282;background-color:#f0f7ff;">（改规格需停机），自建节点上的实例</font>**<font style="color:#2c5282;background-color:#f0f7ff;">只改 K8s 层资源</font>**<font style="color:#2c5282;background-color:#f0f7ff;">。前端无需区分，</font>`<font style="color:#333;background-color:#f0f7ff;">resize/options</font>`<font style="color:#2c5282;background-color:#f0f7ff;"> 会返回 </font>`<font style="color:#333;background-color:#f0f7ff;">backing</font>`<font style="color:#2c5282;background-color:#f0f7ff;"> 字段（</font>`<font style="color:#333;background-color:#f0f7ff;">volc</font>`<font style="color:#2c5282;background-color:#f0f7ff;"> / </font>`<font style="color:#333;background-color:#f0f7ff;">cluster</font>`<font style="color:#2c5282;background-color:#f0f7ff;">）供提示文案使用。</font>

<font style="color:#2c5282;background-color:#f0f7ff;">注意：</font>**<font style="color:#2c5282;background-color:#f0f7ff;">磁盘扩容后需在节点侧让文件系统用上新容量</font>**<font style="color:#2c5282;background-color:#f0f7ff;">：数据盘为</font>**<font style="color:#2c5282;background-color:#f0f7ff;">整盘格式化</font>**<font style="color:#2c5282;background-color:#f0f7ff;">（无分区表），故 ext4 执行 </font>`<font style="color:#333;background-color:#f0f7ff;">resize2fs $(findmnt -no SOURCE /data)</font>`<font style="color:#2c5282;background-color:#f0f7ff;">、xfs 执行 </font>`<font style="color:#333;background-color:#f0f7ff;">xfs_growfs /data</font>`<font style="color:#2c5282;background-color:#f0f7ff;">，</font>**<font style="color:#2c5282;background-color:#f0f7ff;">不需要 </font>**`**<font style="color:#333;background-color:#f0f7ff;">growpart</font>**`<font style="color:#2c5282;background-color:#f0f7ff;">；系统盘有分区表，需先 </font>`<font style="color:#333;background-color:#f0f7ff;">growpart /dev/vda 1</font>`<font style="color:#2c5282;background-color:#f0f7ff;"> 再 </font>`<font style="color:#333;background-color:#f0f7ff;">resize2fs /dev/vda1</font>`<font style="color:#2c5282;background-color:#f0f7ff;">（xfs 用 </font>`<font style="color:#333;background-color:#f0f7ff;">xfs_growfs /</font>`<font style="color:#2c5282;background-color:#f0f7ff;">）。平台不代做宿主机操作，会在变更结果的 </font>`<font style="color:#333;background-color:#f0f7ff;">node_action_required</font>`<font style="color:#2c5282;background-color:#f0f7ff;"> 中返回该指引。</font>

<font style="color:#2c5282;background-color:#f0f7ff;">注意：</font>**<font style="color:#2c5282;background-color:#f0f7ff;">执行顺序</font>**<font style="color:#2c5282;background-color:#f0f7ff;">：一次请求同时包含多项时，按「</font>**<font style="color:#2c5282;background-color:#f0f7ff;">系统盘 → 数据盘 → CPU/内存/GPU 卡数</font>**<font style="color:#2c5282;background-color:#f0f7ff;">」串行执行；任一步失败立即终止，任务标记为 </font>`<font style="color:#333;background-color:#f0f7ff;">failed</font>`<font style="color:#2c5282;background-color:#f0f7ff;">，已完成的步骤保留在 </font>`<font style="color:#333;background-color:#f0f7ff;">steps</font>`<font style="color:#2c5282;background-color:#f0f7ff;"> 中。</font>

### <font style="color:#2c3e50;">65. 提交资源变更（磁盘 / CPU / 内存 / GPU 卡数）</font>
```plain
POST /api/v1/instances/{instance_id}/resize?tenant_id={tenant_id}
```

**请求头**：

```http
Authorization: Bearer <JWT_ACCESS_TOKEN>
Content-Type: application/json
```

**请求体**（各项均可选，至少给一项；同时给多项时按「**系统盘 → 数据盘 → CPU/内存/GPU 卡数**」串行执行）：

```json
{
  "systemDiskGb": 200,
  "diskGb": 300,
  "cpu": "8",
  "memory": "32Gi",
  "instanceTypeId": "ecs.g1v.16xlarge",
  "gpuCount": 2,
  "confirmStop": true
}
```

**参数说明**：

| **<font style="color:#2c3e50;">参数</font>** | **<font style="color:#2c3e50;">类型</font>** | **<font style="color:#2c3e50;">必填</font>** | **<font style="color:#2c3e50;">说明</font>** |
| --- | --- | --- | --- |
| `<font style="color:#333;">systemDiskGb</font>` | int | 否 | 系统盘目标**总容量**（GiB），只扩不缩；下限 20、上限 2048，须大于当前容量。扩容后节点侧需 `<font style="color:#333;">growpart</font>`<br/> + `<font style="color:#333;">resize2fs</font>`<br/> 才能用上新容量 |
| `<font style="color:#333;">diskGb</font>` | int | 否 | 数据盘目标**总容量**（GiB），只扩不缩；**下限 20**、须大于当前容量，上限 65536。**仅当下单时申请过数据盘才可扩**，没有数据盘时请改用 `<font style="color:#333;">systemDiskGb</font>`<br/>。低于下限、小于/等于当前容量都会在提交时直接返回 `<font style="color:#333;">success=false</font>`<br/>（不会建任务） |
| `<font style="color:#333;">cpu</font>` | string | 否 | 目标 CPU，如 `<font style="color:#333;">"8"</font>`<br/> / `<font style="color:#333;">"500m"</font>`<br/>；**下限 100m（0.1 核）**，过小直接返回 `<font style="color:#333;">ResourceTooSmall</font>` |
| `<font style="color:#333;">memory</font>` | string | 否 | 目标内存，如 `<font style="color:#333;">"32Gi"</font>`<br/>；**下限 128Mi**，过小直接返回 `<font style="color:#333;">ResourceTooSmall</font>` |
| `<font style="color:#333;">instanceTypeId</font>` | string | 否 | 火山实例的目标**规格 ID**（规格决定 vCPU+内存组合）。GPU 实例只能取 `<font style="color:#333;">resize/options</font>`<br/> 里 `<font style="color:#333;">gpu_targets[]</font>`<br/> 中**同型号**的规格；CPU 实例只能取 `<font style="color:#333;">cpu_targets[]</font>`<br/> 中**同规格族**的规格。只传 `<font style="color:#333;">cpu</font>`<br/> + `<font style="color:#333;">memory</font>`<br/> 时后端会按当前规格族（GPU 还要求同卡数）自动匹配规格，匹配不到会返回 `<font style="color:#333;">CpuTargetUnavailable</font>`<br/> 并附带可选组合 |
| `<font style="color:#333;">gpuCount</font>` | int | 否 | 目标 GPU 卡数（**同型号、只升不降**）。只传 `<font style="color:#333;">gpuCount</font>`<br/> 时后端自动按「同型号 + 该卡数」挑选可售规格并换算 `<font style="color:#333;">instanceTypeId</font>`<br/>；目标规格的 vCPU / 内存会自动用于 Pod limits（显式传 `<font style="color:#333;">cpu</font>`<br/> / `<font style="color:#333;">memory</font>`<br/> 时以传入值为准） |
| `<font style="color:#333;">confirmStop</font>` | bool | 否 | 改规格需停机、且实例仍在承载运行中 Pod 时必须为 `<font style="color:#333;">true</font>`<br/>，否则接口返回「需要确认停机」而不执行 |


<font style="color:#2c5282;background-color:#f0f7ff;">注意：</font>**<font style="color:#2c5282;background-color:#f0f7ff;">规格变更类型约束（硬约束）</font>**<font style="color:#2c5282;background-color:#f0f7ff;">：</font>

+ **<font style="color:#2c5282;background-color:#f0f7ff;">GPU 实例</font>**<font style="color:#2c5282;background-color:#f0f7ff;">：只能改磁盘 / CPU / 内存，以及在同一 GPU 型号内升卡数（1 → N）；不能改为 CPU 规格，也不能换其它 GPU 型号。</font>
+ **<font style="color:#2c5282;background-color:#f0f7ff;">CPU 实例</font>**<font style="color:#2c5282;background-color:#f0f7ff;">：只能改磁盘 / CPU / 内存；不能改为 GPU 规格。</font>
+ <font style="color:#2c5282;background-color:#f0f7ff;">跨规格族的请求会在入队前被拒绝，</font>`<font style="color:#333;background-color:#f0f7ff;">code</font>`<font style="color:#2c5282;background-color:#f0f7ff;"> 为 </font>`<font style="color:#333;background-color:#f0f7ff;">SpecCrossFamilyForbidden</font>`<font style="color:#2c5282;background-color:#f0f7ff;"> / </font>`<font style="color:#333;background-color:#f0f7ff;">GpuModelChangeForbidden</font>`<font style="color:#2c5282;background-color:#f0f7ff;"> / </font>`<font style="color:#333;background-color:#f0f7ff;">GpuScaleDownUnsupported</font>`<font style="color:#2c5282;background-color:#f0f7ff;">，不会产生变更任务。</font>
+ <font style="color:#2c5282;background-color:#f0f7ff;">升卡要求 Pod </font>**<font style="color:#2c5282;background-color:#f0f7ff;">已挂载工作区卷</font>**<font style="color:#2c5282;background-color:#f0f7ff;">（PVC 或节点本地目录）。创建时未申请数据盘的实例没有任何工作区卷，重建 Pod 会丢失容器内数据，此时在入队前返回 </font>`<font style="color:#333;background-color:#f0f7ff;">code = WorkspaceStorageMissing</font>`<font style="color:#2c5282;background-color:#f0f7ff;">，提示「该实例创建时未申请数据盘，升卡会重建 Pod 导致容器内数据丢失，请先扩容数据盘或迁移数据」。有卷的实例直接放行。</font>
+ <font style="color:#2c5282;background-color:#f0f7ff;">GPU 卡数升配走</font>**<font style="color:#2c5282;background-color:#f0f7ff;">镜像原地变配</font>**<font style="color:#2c5282;background-color:#f0f7ff;">：云端改规格后等节点重新上报 </font>`<font style="color:#333;background-color:#f0f7ff;">nvidia.com/gpu</font>`<font style="color:#2c5282;background-color:#f0f7ff;">，再用</font>**<font style="color:#2c5282;background-color:#f0f7ff;">同一镜像</font>**<font style="color:#2c5282;background-color:#f0f7ff;">按新卡数重建 Pod；镜像无需重建，但镜像本身需支持多卡（如多卡训练需镜像自带 NCCL）。</font>

**响应示例（受理成功）**：

```json
{
  "success": true,
  "message": "资源变更已受理，请轮询任务状态",
  "task_id": "rsz_9f2c8b7a1d4e6f30",
  "status": "pending",
  "task_url": "/api/v1/instances/a1b2c3d4e5f6/resize/tasks/rsz_9f2c8b7a1d4e6f30"
}
```

**响应示例（业务校验失败，HTTP 200）**：

```json
{
  "success": false,
  "message": "云盘只支持扩容，不支持缩容（当前 300GiB，目标 200GiB）",
  "code": ""
}
```

<font style="color:#2c5282;background-color:#f0f7ff;">说明：返回的 </font>`<font style="color:#333;background-color:#f0f7ff;">volc_instance_id</font>`<font style="color:#2c5282;background-color:#f0f7ff;"> 在受理阶段可能为空，服务端拿到后自动补齐；届时 </font>`<font style="color:#333;background-color:#f0f7ff;">status_message</font>`<font style="color:#2c5282;background-color:#f0f7ff;"> 会被清空。前端只需展示「创建中」，并通过接口 71 / 72 轮询获取 IP、SSH 信息与最终状态。</font>

<font style="color:#2c5282;background-color:#f0f7ff;">注意：</font>**<font style="color:#2c5282;background-color:#f0f7ff;">重复提交保护</font>**<font style="color:#2c5282;background-color:#f0f7ff;">：未带 </font>`<font style="color:#333;background-color:#f0f7ff;">idempotencyKey</font>`<font style="color:#2c5282;background-color:#f0f7ff;"> 时，若 120 秒内出现</font>**<font style="color:#2c5282;background-color:#f0f7ff;">参数完全相同</font>**<font style="color:#2c5282;background-color:#f0f7ff;">（region / zone / 规格 / 计费方式 / 系统盘 / 数据盘 / count）且仍在创建中的下单，服务端直接返回那批在途实例（</font>`<font style="color:#333;background-color:#f0f7ff;">deduped: true</font>`<font style="color:#2c5282;background-color:#f0f7ff;">），不会重复购买；前端按正常「受理成功」流程展示即可。</font>**<font style="color:#2c5282;background-color:#f0f7ff;">并发重复提交（用户连点 / 前端并发重试）同样会被合并</font>**<font style="color:#2c5282;background-color:#f0f7ff;">：两个相同请求同时到达时，后到的那个也会返回先到者刚登记的实例。窗口可用环境变量 </font>`<font style="color:#333;background-color:#f0f7ff;">VOLC_CPU_DEDUPE_WINDOW</font>`<font style="color:#2c5282;background-color:#f0f7ff;"> 调整。</font>

<font style="color:#2c5282;background-color:#f0f7ff;">注意：</font>**<font style="color:#2c5282;background-color:#f0f7ff;">创建失败原因可见</font>**<font style="color:#2c5282;background-color:#f0f7ff;">：后台下单失败时该实例被置为 </font>`<font style="color:#333;background-color:#f0f7ff;">status: "error"</font>`<font style="color:#2c5282;background-color:#f0f7ff;">，失败原因写入 </font>`<font style="color:#333;background-color:#f0f7ff;">status_message</font>`<font style="color:#2c5282;background-color:#f0f7ff;">（实例列表 71 / 详情 72 均返回该字段），前端直接展示即可。</font>

<font style="color:#2c5282;background-color:#f0f7ff;">注意：</font>**<font style="color:#2c5282;background-color:#f0f7ff;">失败不会被自动重试创建</font>**<font style="color:#2c5282;background-color:#f0f7ff;">：下单失败后该记录即为终态，服务重启、列表刷新都不会再拿它去下单（同一实例的自动下单尝试最多 2 次）；「创建中」超过 15 分钟仍没有实例 ID 的记录会被判为「上次下单中断」并置 </font>`<font style="color:#333;background-color:#f0f7ff;">error</font>`<font style="color:#2c5282;background-color:#f0f7ff;">，不再自动补单。前端拿到 </font>`<font style="color:#333;background-color:#f0f7ff;">error</font>`<font style="color:#2c5282;background-color:#f0f7ff;"> 后按提示处理后</font>**<font style="color:#2c5282;background-color:#f0f7ff;">重新调用本接口</font>**<font style="color:#2c5282;background-color:#f0f7ff;">即可。</font>

<font style="color:#2c5282;background-color:#f0f7ff;">注意：</font>**<font style="color:#2c5282;background-color:#f0f7ff;">失败冷却</font>**<font style="color:#2c5282;background-color:#f0f7ff;">：同一租户、同参数（region / zone / 规格 / 计费方式 / 系统盘 / 数据盘）刚刚下单失败时，60 秒内再次提交会直接返回 </font>`<font style="color:#333;background-color:#f0f7ff;">success: false</font>`<font style="color:#2c5282;background-color:#f0f7ff;">，</font>`<font style="color:#333;background-color:#f0f7ff;">message</font>`<font style="color:#2c5282;background-color:#f0f7ff;"> 带上上一次的失败原因，不会产生新记录、也不会发起新的下单（可用 </font>`<font style="color:#333;background-color:#f0f7ff;">VOLC_CPU_FAILURE_COOLDOWN</font>`<font style="color:#2c5282;background-color:#f0f7ff;"> 调整，设为 0 关闭）。</font>

**<font style="color:#2c5282;background-color:#f0f7ff;">配额熔断</font>**<font style="color:#2c5282;background-color:#f0f7ff;">：下单被服务端以配额类错误拒绝（如 </font>`<font style="color:#333;background-color:#f0f7ff;">QuotaExceeded.MaximumEips</font>`<font style="color:#2c5282;background-color:#f0f7ff;">）时，该租户在对应 region 的 CPU 下单会熔断 300 秒，期间任何规格 / 磁盘组合的提交都直接返回 </font>`<font style="color:#333;background-color:#f0f7ff;">success: false</font>`<font style="color:#2c5282;background-color:#f0f7ff;">（带上次配额失败原因和剩余秒数），不落记录、不发起下单；有实例下单成功会自动解除。可用 </font>`<font style="color:#333;background-color:#f0f7ff;">VOLC_CPU_QUOTA_COOLDOWN</font>`<font style="color:#2c5282;background-color:#f0f7ff;"> 调整，设为 0 关闭。配额属于账号级限制，需在账号侧释放闲置实例 / 公网 IP 或提升配额。</font>

<font style="color:#2c5282;background-color:#f0f7ff;">注意：</font>**<font style="color:#2c5282;background-color:#f0f7ff;">业务失败统一 HTTP 200 + </font>**`**<font style="color:#333;background-color:#f0f7ff;">success: false</font>**`<font style="color:#2c5282;background-color:#f0f7ff;">：检查不通过时不会创建任何实例记录，</font>`<font style="color:#333;background-color:#f0f7ff;">message</font>`<font style="color:#2c5282;background-color:#f0f7ff;"> 直接给出可读原因，</font>`<font style="color:#333;background-color:#f0f7ff;">checks</font>`<font style="color:#2c5282;background-color:#f0f7ff;"> 列出已执行的检查项、</font>`<font style="color:#333;background-color:#f0f7ff;">errors</font>`<font style="color:#2c5282;background-color:#f0f7ff;"> 给出每一台受理失败的具体原因。</font>

<font style="color:#2c5282;background-color:#f0f7ff;">说明：多台购买时，只要有一台受理成功即 </font>`<font style="color:#333;background-color:#f0f7ff;">success: true</font>`<font style="color:#2c5282;background-color:#f0f7ff;"> 且 </font>`<font style="color:#333;background-color:#f0f7ff;">partial: true</font>`<font style="color:#2c5282;background-color:#f0f7ff;">（</font>`<font style="color:#333;background-color:#f0f7ff;">errors</font>`<font style="color:#2c5282;background-color:#f0f7ff;"> 列出失败的那几台）。</font>

<font style="color:#2c5282;background-color:#f0f7ff;">说明：实例默认随购买分配</font>**<font style="color:#2c5282;background-color:#f0f7ff;">弹性公网 IP</font>**<font style="color:#2c5282;background-color:#f0f7ff;">（按流量后付费），公网单价可用接口 78 查询；如需内网使用可关闭该项（服务端配置）。</font>

<font style="color:#2c5282;background-color:#f0f7ff;">说明：未传 </font>`<font style="color:#333;background-color:#f0f7ff;">pricing</font>`<font style="color:#2c5282;background-color:#f0f7ff;"> 时 </font>`<font style="color:#333;background-color:#f0f7ff;">price_per_hour</font>`<font style="color:#2c5282;background-color:#f0f7ff;"> 初始为 </font>`<font style="color:#333;background-color:#f0f7ff;">0</font>`<font style="color:#2c5282;background-color:#f0f7ff;">，服务端会在后台按实时价补录，稍后查询实例详情即可看到折后价。</font>

### <font style="color:#2c3e50;">79. 独立 CPU：重启</font>
```plain

```

**功能**：对独立 CPU 云主机发起重启（云侧 `<font style="color:#333;">RebootInstances</font>`）。仅**运行中**实例可重启；实例受理后先返回 `<font style="color:#333;">starting</font>`，真实状态由后台线程等待并回写，避免接口返回 `<font style="color:#333;">running</font>` 时机器仍在重启。

**参数说明**：

```json
}
```

<font style="color:#2c5282;background-color:#f0f7ff;">注意：关机态实例不能「重启」，请先调用接口 74 开机；有进行中的变配任务时会被拒绝（</font>`<font style="color:#333;background-color:#f0f7ff;">code: operation_inflight</font>`<font style="color:#2c5282;background-color:#f0f7ff;">）。</font>

### <font style="color:#2c3e50;">96. 按订单号回收孤儿机器</font>
```plain
POST /api/v1/orders/{order_id}/reclaim?authKey={ADMIN_AUTH_KEY}&node_name=&volc_instance_id=&dry_run=false
```

**功能**：回收「云上已创建、平台没接管」的孤儿机器。GPU 采购流程若在「创建 Pod」之前中断（进程重启 / 异常），云主机可能已在计费、节点已自行 join 集群，但平台没有对应的正常实例记录，常规释放接口找不到它。本接口按订单反查区域与实例清单，逐台执行：**删除（按量）/ 退订（包月）→ 解绑公网 IP（不释放，留池给下次创建复用）→ 把对应节点踢出集群**。**需要管理鉴权。**

**参数说明**：

| **<font style="color:#2c3e50;">参数</font>** | **<font style="color:#2c3e50;">类型</font>** | **<font style="color:#2c3e50;">必填</font>** | **<font style="color:#2c3e50;">说明</font>** |
| --- | --- | --- | --- |
| `<font style="color:#333;">order_id</font>` | path | 是 | 订单 ID |
| `<font style="color:#333;">node_name</font>` | query | 否 | 只回收该节点对应的那一台；不传 = 整单全部 |
| `<font style="color:#333;">volc_instance_id</font>` | query | 否 | 只回收该机器 ID（优先级高于 `<font style="color:#333;">node_name</font>`<br/>） |
| `<font style="color:#333;">dry_run</font>` | query bool | 否 | `<font style="color:#333;">true</font>`<br/> 只返回待回收清单，不动任何资源；默认 `<font style="color:#333;">false</font>` |


**响应示例**：

```json
{
  "success": true,
  "order_id": "ord_041c1e511bf04d49",
  "region": "cn-beijing",
  "billing_mode": "on_demand",
  "action": "delete",
  "dry_run": false,
  "targets": [
    {
      "volc_instance_id": "i-yey2tufcow5i3z5ya8gb",
      "node_name": "gpu-node-01",
      "action": "delete",
      "result": "reclaimed",
      "error": null,
      "eip_allocation_id": "eip-xxxx",
      "eip_detached": true,
      "eip_detach_pending": false,
      "node_kicked": true,
      "node_error": null
    }
  ],
  "reclaimed": ["i-yey2tufcow5i3z5ya8gb"],
  "failed": [],
  "message": "已回收 1 台机器，公网 IP 已解绑保留（供后续复用），对应集群节点已清理"
}
```

<font style="color:#2c5282;background-color:#f0f7ff;">说明：</font>**<font style="color:#2c5282;background-color:#f0f7ff;">幂等</font>**<font style="color:#2c5282;background-color:#f0f7ff;">：云侧实例已不存在时该台记为 </font>`<font style="color:#333;background-color:#f0f7ff;">result=already_gone</font>`<font style="color:#2c5282;background-color:#f0f7ff;">，按已回收处理，可重复调用。</font>

<font style="color:#2c5282;background-color:#f0f7ff;">说明：</font>**<font style="color:#2c5282;background-color:#f0f7ff;">公网 IP 只解绑不释放</font>**<font style="color:#2c5282;background-color:#f0f7ff;">：解绑后 IP 回到可用池，下次 CPU / GPU 创建会优先复用，避免反复申请释放打满公网 IP 配额；机器删除是异步的，首次解绑若撞「实例仍在用」，会转后台每 10s 重试（最长 300s），此时 </font>`<font style="color:#333;background-color:#f0f7ff;">eip_detach_pending=true</font>`<font style="color:#2c5282;background-color:#f0f7ff;">。</font>

<font style="color:#2c5282;background-color:#f0f7ff;">说明：业务失败（订单不存在 / 机器不属于该订单等）同样返回 </font>**<font style="color:#2c5282;background-color:#f0f7ff;">200 + </font>**`**<font style="color:#333;background-color:#f0f7ff;">success=false</font>**`<font style="color:#2c5282;background-color:#f0f7ff;">，</font>`<font style="color:#333;background-color:#f0f7ff;">message</font>`<font style="color:#2c5282;background-color:#f0f7ff;"> 给出具体原因。</font>
