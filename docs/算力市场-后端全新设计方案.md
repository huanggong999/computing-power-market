# 算力市场后端全新设计方案

## 一、设计原则

- **全新设计**：不继承、不扩展任何现有表（`sys_ecs`、`sys_home_ecs`、`sys_price_entity` 等均不使用）
- **领域驱动**：以算力市场为核心域，独立建表、独立 API、独立管理模块
- **前后端对齐**：数据库字段与前端 `GpuCard`、`GpuFilterPanel` 数据结构 1:1 映射

---

## 二、数据库设计

### 2.1 表清单

| 表名 | 说明 | 数据量预估 |
|------|------|-----------|
| `gpu_resource` | GPU 资源主表（机器维度） | 千级 |
| `gpu_resource_spec` | GPU 规格定义表（型号维度） | 百级 |
| `gpu_region` | 地区配置表 | 十级 |
| `gpu_zone` | 专区配置表 | 十级 |
| `gpu_resource_price` | 资源价格表（支持多计费方式） | 千级 |
| `gpu_resource_stock` | 资源实时库存表（独立，便于高频更新） | 千级 |

### 2.2 `gpu_resource` — GPU 资源主表

```sql
CREATE TABLE gpu_resource (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '资源ID',
    resource_no     VARCHAR(32) NOT NULL COMMENT '资源编号，如 RES-2024-001',
    machine_id      VARCHAR(32) NOT NULL COMMENT '机器编号，如 D21机',
    machine_uuid    VARCHAR(64) NOT NULL COMMENT '机器唯一标识，如 3y80s00ajm',

    -- 关联维度
    region_code     VARCHAR(32) NOT NULL COMMENT '地区编码，如 northwest-b',
    zone_code       VARCHAR(32) COMMENT '专区编码，如 v100',
    spec_id         BIGINT NOT NULL COMMENT '关联规格ID',

    -- GPU 配置
    gpu_count       INT NOT NULL DEFAULT 1 COMMENT '单台机器GPU数量',
    gpu_driver      VARCHAR(64) COMMENT 'GPU驱动版本，如 580.105.08',
    cuda_version    VARCHAR(32) COMMENT 'CUDA版本，如 13.0',
    cache_optimized TINYINT(1) DEFAULT 0 COMMENT '是否缓存优化 0否 1是',

    -- CPU 与内存
    cpu_cores       INT NOT NULL COMMENT 'CPU核心数',
    cpu_model       VARCHAR(128) NOT NULL COMMENT 'CPU型号全称，如 Xeon(R) Platinum 8470Q',
    memory_size     VARCHAR(32) NOT NULL COMMENT '内存大小，如 92 GB',

    -- 存储
    system_disk     VARCHAR(32) NOT NULL COMMENT '系统盘，如 30 GB',
    data_disk       VARCHAR(32) NOT NULL COMMENT '数据盘，如 50 GB',
    expandable      VARCHAR(32) COMMENT '可扩容容量，如 595 GB',

    -- 租期
    rentable_until  DATE NOT NULL COMMENT '可租用截止日期',

    -- 状态
    status          TINYINT(1) NOT NULL DEFAULT 1 COMMENT '状态 1上架 2下架 3维护中',

    -- 审计字段
    create_by       VARCHAR(64),
    create_by_id    BIGINT,
    create_time     DATETIME DEFAULT CURRENT_TIMESTAMP,
    update_by       VARCHAR(64),
    update_by_id    BIGINT,
    update_time     DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    del_flag        TINYINT(1) DEFAULT 0,

    UNIQUE KEY uk_machine_uuid (machine_uuid),
    INDEX idx_region_code (region_code),
    INDEX idx_zone_code (zone_code),
    INDEX idx_spec_id (spec_id),
    INDEX idx_status (status)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='GPU资源主表';
```

## 八、关键决策

### 决策 1：库存独立表 `gpu_resource_stock`
- **选择**：库存单独建表，不与主表混存
- **理由**：库存字段（availableCount）需要高频更新（可能被调度系统/定时任务更新），独立表可减少锁竞争，支持异步同步

### 决策 2：价格独立表 `gpu_resource_price`
- **选择**：一资源多价格（按量/包日/包周/包月），独立价格表
- **理由**：支持灵活的多计费方式，避免主表字段膨胀，便于后续扩展新计费模式

### 决策 3：规格独立表 `gpu_resource_spec`
- **选择**：GPU 型号定义独立表
- **理由**：型号信息（model/vram/architecture）属于元数据，多资源可复用同一规格，管理端可独立维护型号库

### 决策 4：管理端使用抽屉而非新页面编辑
- **选择**：GPU 资源编辑使用抽屉（Drawer）组件
- **理由**：表单字段较多（40+），抽屉可以保持列表上下文，减少页面跳转
