二、JWT 认证说明

⚠️ 重要安全变更
本系统已全面升级为 JWT Bearer Token 认证，不再支持旧的 X-Tenant-ID Header 明文认证方式。

认证流程

第一步：调用 POST /api/v1/auth/token 使用 tenant_id + api_key 换取 JWT Access Token。

第二步：后续所有受保护接口必须在请求头中携带：

Authorization: Bearer <JWT_ACCESS_TOKEN>

第三步：如果请求参数或 Body 中也传了 tenant_id / tenantId，后端会强制校验其与 Token 中的 tenant_id 是否一致，不一致返回 403 Forbidden。

字段命名兼容：创建类接口支持前端常用 camelCase（如 tenantId、gpuSpec、machineId、pageSize），同时兼容后端 snake_case（如 tenant_id、gpu_spec、machine_id、page_size）。本文示例优先使用 camelCase。

Token 载荷示例

{
  "tenant_id": "tenant_001",
  "tenant_name": "AI科技公司",
  "role": "user",
  "iat": 1716940000,
  "exp": 1717544800,
  "type": "access"
}

环境变量配置

环境变量说明默认值
JWT_SECRET_KEYJWT 签名密钥（生产环境必须修改为强随机字符串）gpu-scheduler-jwt-secret-key-change-me-in-production
JWT_ALGORITHM签名算法HS256
JWT_ACCESS_TOKEN_EXPIRE_DAYSToken 有效期（天）7
API_KEY签发 Token 时的校验密钥（演示环境使用全局密钥）demo-api-key-2024
💡 生产环境建议：务必修改 JWT_SECRET_KEY 和 API_KEY，使用 32 字节以上的强随机字符串。建议将 API_KEY 校验替换为数据库中的租户独立密码/AKSK，或对接统一认证平台（SSO/OAuth2）。

参数类型必填说明

resource.cpuModelstring是CPU型号，由前端传入
resource.memorystring是内存
resource.systemDiskstring是系统盘
resource.dataDiskstring是数据盘

billing.py计费服务（价格计算/计费记录/续费）
instance_manager.py容器实例生命周期管理（状态/SSH/密码/定时关机）
market_data.py算力市场数据（地区/GPU型号/可租用实例）
requirements.txtPython 依赖包
API.mdMarkdown 接口文档
API.htmlHTML 接口文档（本文件）

对接说明

1. 纯本地演示：当前 instance_manager.py 使用 JSON 文件持久化实例数据，无需连接 K8s 即可运行所有 API。

2. 对接真实 K8s：若需操作真实集群，instance_manager.start/stop/restart 可扩展调用 k8s_client 对 Pod 的实际操作；原有 /api/v1/gpu/pod/* 接口可直接使用。

3. SSH 远程登录：当前返回 SSH 连接信息（主机、端口、用户名、密码），如需实现真正的 WebSSH/JupyterLab 代理，可在 tools 中扩展代理跳转逻辑。

4. JWT 安全提醒：生产环境务必修改 JWT_SECRET_KEY 和 API_KEY 环境变量，使用强随机字符串，防止 Token 被伪造。建议将 API_KEY 校验替换为数据库中的租户独立密码/AKSK，或对接统一认证平台（SSO/OAuth2）。
