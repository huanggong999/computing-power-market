# AutoDL 创建实例页对齐差异说明

对比对象：

- 本地页面：`http://localhost:4173/#/computeRent?resourceId=16`
- 参考页面：AutoDL 创建实例页（用户本机已登录可访问）

## 当前本地页面概况

本地页面当前已经具备：

- 顶部导航与登录用户展示
- 返回按钮与“确认租用”标题
- GPU/CPU 资源基础配置卡片
- 镜像类型与镜像版本选择
- 计费方式、租用数量
- 账户余额展示
- 服务协议勾选与确认租用按钮

但整体仍是“确认页/详情卡片”结构，和 AutoDL 的“创建实例表单”结构存在明显差异。

## AutoDL 页面关键结构

AutoDL 页面从上到下是单页表单流程：

1. 顶部公告与导航。
2. 面包屑：`算力市场 / 创建实例`。
3. 计费方式：按量计费、包日、包周、包月，并提供“计费规则”链接和说明文案。
4. 选择主机：表格展示主机候选项，包含主机 ID、算力型号/显存、空闲 GPU、每 GPU 分配、CPU 型号、硬盘、驱动/CUDA、单卡价格。
5. GPU 数量：用 1 到空闲 GPU 数量的单选按钮选择卡数。
6. 数据盘：展示免费数据盘，并可勾选“需要扩容”。
7. 实例规格：根据主机和 GPU 数量实时汇总 GPU、CPU、内存、系统盘、数据盘。
8. 镜像：先选择基础镜像、社区镜像、我的镜像，再通过下拉选择具体框架/版本/Python/CUDA 组合；包含“没有我要的环境？”入口和基础镜像说明。
9. 底部费用与操作区：日常费用、配置费用、费用明细、账户余额、余额不足去充值、取消、创建并开机。
10. 费用明细浮层：展示计费公式、会员折扣、实例和数据盘等计费项的原价、折扣金额、最终价格。

## 差异与需要补齐的工作

### 1. 页面定位与标题

当前本地页面标题是“确认租用”，更像二次确认页；AutoDL 是“创建实例”。

需要：

- 将页面定位调整为“创建实例/租用实例”流程。
- 增加面包屑 `算力市场 / 创建实例`。
- 保留返回能力，但不应作为页面主视觉标题的一部分。

### 2. 计费方式区域不完整

本地页面只有按小时、按天、按月；AutoDL 有按量计费、包日、包周、包月，并有“计费规则”链接和说明。

需要：

- 补齐包周选项。
- 将 `hourly` 的显示文案调整为“按量计费”。
- 增加“计费规则”入口。
- 增加计费说明：创建完主机后仍然可以转换计费方式；按量计费价格以实例开机时为准。
- 切换计费方式时同步刷新单价、费用明细和提交参数。

### 4. 主机选择表格缺失

本地页面直接展示单个资源配置卡片；AutoDL 在“选择主机”中使用表格，即使只有一个候选主机也以表格行呈现。

需要：

- 将当前 GPU 配置卡片改造成“选择主机”表格，或至少在主区域增加主机选择表格。
- 表格列应包含：
  - 主机 ID/机器编号
  - 算力型号/显存
  - 空闲 GPU（如 `5 / 10`）
  - 每 GPU 分配（CPU、内存）
  - CPU 型号
  - 硬盘（数据盘、可扩容）
  - 驱动/CUDA
  - 价格（单卡）
- 当前 `resourceId` 仍可默认选中对应行。
- 点击表格行应能切换选中主机，并联动 GPU 数量、规格汇总和价格。

### 5. GPU 数量选择形式需要对齐

本地页面使用数字输入器；AutoDL 使用从 1 到空闲 GPU 数量的单选按钮。

需要：

- 改为单选按钮组，选项从 `1` 到当前主机 `availableCount`。
- 默认数量应来自路由或列表页传参；没有传参时默认 1。
- 选择数量后实时更新实例规格、配置费用和提交参数。

### 6. 数据盘扩容能力缺失

本地页面只展示系统盘和数据盘信息；AutoDL 有免费 50GB 数据盘，并支持“需要扩容”。

需要：

- 增加数据盘区域：展示免费数据盘容量。
- 增加“需要扩容”复选框。
- 勾选后展示扩容容量输入/选择项、可扩容上限、扩容费用。
- 扩容费用计入日常费用或费用明细。
- 后端资源详情需返回 `dataDisk`、`expandable` 可被前端解析为容量数值。

### 7. 实例规格汇总缺失

本地页面分散展示硬件配置；AutoDL 有统一“实例规格”摘要，且随 GPU 数量实时变化。

需要：

- 增加“实例规格”区块。
- 汇总字段包括：GPU 型号、CPU、内存、系统盘、数据盘。
- GPU 显示为 `型号 * N卡`。
- CPU/内存按单卡分配乘以 GPU 数量计算。
- 数据盘显示免费容量及扩容后的总容量。

### 8. 费用区不一致

本地页面按 PyTorch/TensorFlow/Miniconda 分类；AutoDL 先按镜像来源分类：基础镜像、社区镜像、我的镜像，再通过下拉选择具体环境。

需要：

- 将镜像选择调整为来源分类：基础镜像、社区镜像、我的镜像。
- 社区镜像显示 hot 标签。
- 增加“没有我要的环境？”链接入口。
- 基础镜像下展示说明文案：基础镜像包含常用基本软件，如深度学习框架、Miniconda 等；如需其他软件可创建后安装。
- 镜像下拉搜索/选择项应支持显示框架名、框架版本、Python 版本、CUDA 版本。
- 后端镜像接口需要支持镜像来源、框架名、框架版本、Python、CUDA、是否热门等字段。

### 8. 费用区不一致

本地页面费用卡片只有在计算结果存在时才显示，且展示单价/数量/小计/优惠/总额；AutoDL 底部固定展示日常费用、配置费用、费用明细、账户余额和充值入口。

需要：

- 费用区改为页面底部汇总条或靠近底部的固定操作区。
- 常驻展示：
  - 日常费用（如数据盘扩容日费）
  - 配置费用（实例费用，按当前计费方式显示单位）
  - 费用明细入口
  - 账户余额
  - 余额不足去充值
  - 取消
  - 创建并开机
- 费用明细入口应显示弹层或 popover，至少包含实例费用、数据盘费用、折扣金额、最终价格。
- 余额不足时创建按钮应禁用或引导充值，文案和状态要明确。

### 9. 提交动作不一致

本地按钮是“确认租用”；AutoDL 是“创建并开机”，旁边有“取消”。

需要：

- 提交按钮文案调整为“创建并开机”。
- 增加“取消”按钮，返回算力市场或上一页。
- 提交前校验镜像、GPU 数量、余额、库存、协议/服务条款。
- 创建成功后的跳转目标应明确：实例控制台或订单详情。

### 10. 服务协议展示方式差异

本地显式勾选服务协议；AutoDL 当前页面截图中未突出协议勾选。

需要：

- 决策是否保留协议勾选。如果保留，视觉上应弱化到费用区附近，避免破坏 AutoDL 式底部操作区。
- 若取消显式勾选，需要确认合规要求。

### 11. 后端数据能力不足

为了对齐 AutoDL，当前单个资源详情接口不足以支撑页面。

需要：

- 增加或扩展创建页初始化接口，返回：
  - 可选主机列表
  - 默认选中主机
  - 每台主机空闲/总 GPU
  - 单卡 CPU/内存分配
  - 数据盘免费容量、可扩容容量、扩容价格
  - 多计费周期价格
  - 镜像来源与版本列表
  - 账户余额
- 费用计算接口支持：计费方式、GPU 数量、数据盘扩容、会员折扣。
- 创建订单接口支持：主机 ID、GPU 数量、数据盘扩容、镜像来源、镜像版本、计费方式。

## 建议实施顺序

1. 先改页面信息架构：面包屑、计费方式说明、主机表格、GPU 数量按钮、实例规格区。
2. 再补镜像选择：镜像来源 tabs、镜像版本下拉、说明文案、无环境入口。
3. 再补费用区：日常费用、配置费用、费用明细、余额不足充值、取消/创建并开机。
4. 最后补数据盘扩容、费用明细弹层和后端完整计费能力。

## 验收标准

- 页面首屏结构与 AutoDL 创建实例页一致：面包屑、计费方式、选择主机表格。
- GPU 数量不再使用数字输入器，而是按空闲 GPU 数生成单选按钮。
- 页面有“实例规格”摘要，并随 GPU 数量实时变化。
- 镜像区域按基础镜像/社区镜像/我的镜像组织，支持版本下拉选择。
- 底部费用区常驻展示日常费用、配置费用、费用明细、账户余额、取消、创建并开机。
- 余额不足时展示“余额不足去充值”。
- 所有选择变化都会刷新费用和提交参数。
