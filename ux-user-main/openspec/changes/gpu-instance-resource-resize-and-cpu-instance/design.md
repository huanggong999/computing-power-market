## Context

当前用户端的实例管理页只接入 GPU Pod 实例链路，能够查看实例和执行基础生命周期操作，但不能读取资源变更边界，也不能提交磁盘、CPU/内存或公网带宽变更。现有 GPU 购买流程也没有独立 CPU 云主机入口。

本变更接入 `docs/v2.1：资源变更 & 独立 CPU.md` 定义的接口 64–76。接口由外部实例服务提供，用户端需要通过当前门户后端的适配路径访问，并继续使用现有 Axios 鉴权、Pinia 状态和控制台布局。

## Goals / Non-Goals

**Goals:**

- 在一个实例管理页面中通过 GPU/CPU Tab 隔离两类实例。
- 为 GPU 实例提供基于能力和边界的资源变更交互。
- 支持异步资源变更任务的提交、轮询、历史查看和失败反馈。
- 支持公网带宽的同步扩容和缩容。
- 提供独立 CPU 实例购买、列表、详情和生命周期操作。
- 保持 CPU 实例不加入 GPU/Kubernetes 集群的产品语义。

**Non-Goals:**

- 本期不实现 GPU/CPU 购买时公网 IP 的购买开关和公网计费选择。
- 本期不实现资源变更费用试算、支付扣款和真实的 `RESOURCE_RESIZE` 订单分支；仅保留后续扩展边界。
- 不改变既有 GPU 创建、GPU 开机/关机/重启/释放和监控接口的行为。
- 不在前端自行推断资源上下限或实例来源。

## Decisions

### 1. 以实例类型作为页面级数据边界

实例页面保留现有路由，增加 GPU/CPU Tab。GPU Tab 请求现有 GPU Pod 列表；CPU Tab 请求独立 CPU 列表。两类数据使用统一的页面壳和操作反馈，但使用不同的类型模型、详情字段和操作 API。

**替代方案**：把两类实例合并成一张表。该方案会导致 GPU 专属字段、CPU 字段和操作权限大量条件分支，也容易误调用集群生命周期接口，因此不采用。

### 2. 变更表单由 options 接口驱动

打开 GPU 资源变更时先调用接口 64。表单根据 `current`、`capabilities`、`limits` 和 `backing` 动态决定可编辑项、最小最大值、扩缩容方向和提示文案。前端不复制后端默认上限。

资源变更提交调用接口 65；返回 `task_id` 后调用接口 67 轮询，必要时用接口 66 展示历史任务。磁盘与 CPU/内存一次提交，带宽调用接口 68 单独提交。

### 3. 使用共享操作反馈和轮询机制

GPU 资源变更任务和现有实例生命周期操作都需要防重复提交、显示进行中状态、处理终态和刷新详情。新增的资源变更 composable 复用现有操作状态管理的模式，但不把 CPU 和 GPU 的 API 混在同一组函数中。

### 4. CPU 购买严格使用服务端规格 ID

CPU 购买页先按接口 69 选择地域/可用区，再按接口 70 加载纯 CPU 规格。提交接口 73 时只发送用户选择的 `instanceTypeId`，不允许前端拼接或修改规格参数。计费模式使用接口定义的 `on_demand`、`monthly`、`yearly`。

### 5. 通过来源字段分流操作

GPU 实例继续使用现有 GPU Pod 操作；CPU 实例使用接口 74–76。列表行和详情模型保留 `origin`/实例类型标识，防止 CPU 实例误调用 GPU/Kubernetes 释放路径。

## Risks / Trade-offs

- [外部任务延迟或服务重启清空任务] → 轮询接口 67 使用退避和超时；任务列表仅作为最近历史，最终资源值以详情/列表接口为准。
- [用户在任务执行期间重复提交] → 以实例 ID 维护进行中任务，表单和相关操作按钮在任务未结束前禁用。
- [外部接口路径与门户 `/pc/*` 路由不一致] → 在实现前由后端提供稳定的门户适配接口，前端不直接拼接外部服务地址。
- [CPU 和 GPU 字段结构差异] → 使用独立 TypeScript 类型和渲染分支，共享仅限状态标签、分页和操作反馈组件。
- [CPU 云端购买同步耗时较长] → CPU 购买提交使用长超时、明确的 loading 文案，并在成功后刷新 CPU Tab。

## Migration Plan

1. 先部署后端适配接口和鉴权/租户透传，再发布前端 API 层和类型。
2. 增加 CPU 购买入口和实例 Tab，默认不改变现有 GPU Tab 的请求与操作。
3. 灰度启用 GPU 资源变更入口，验证 options、resize task 和 bandwidth 接口后开放操作按钮。
4. 若外部接口异常，关闭资源变更和 CPU 购买入口即可回滚；GPU 既有列表和生命周期操作保持可用。

## Open Questions

- 门户后端最终暴露的适配路径和统一响应结构需要在联调前确认。
- `orderType=RESOURCE_RESIZE` 仅作为后续支付扩展，不属于本期前端提交参数。
