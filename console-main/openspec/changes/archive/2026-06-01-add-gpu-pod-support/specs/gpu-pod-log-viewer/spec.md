# GPU Pod 日志查看功能

## 概述

GPU Pod 日志查看功能允许用户查看 GPU Pod 实例的容器日志，包括标准输出(stdout)和标准错误(stderr)。这对于调试应用程序、排查问题、监控运行状态非常有用。

## 功能需求

## 新增需求

### 需求:
用户可以查看指定 GPU Pod 实例的容器日志。

#### 场景:
作为实例所有者，我想要查看我的 GPU Pod 实例的容器日志，以便调试应用程序和排查问题。

**输入**：
- instanceId: 实例ID（路径参数）
- tailLines: 返回最后N行日志（查询参数，可选，默认100，最大1000）

**输出**：
- 日志内容：字符串格式，包含多条日志行

**业务规则**：
- 只能查询自己创建的实例的日志
- 实例状态为 running 或 stopped 时都可以查看日志
- 日志内容实时从 GPU Pod 服务获取，不做本地缓存
- 如果实例刚刚创建，可能暂时没有日志

## 接口规范

### 后端接口

```java
@GetMapping("/instances/{id}/logs")
@Operation(summary = "获取Pod日志")
public Result<String> getLogs(
    @PathVariable String id,
    @RequestParam(defaultValue = "100") int tailLines);
```

### 前端 API

```typescript
// 获取Pod日志
export function getInstanceLogs(id: string, tailLines: number = 100) {
  return request.get(`/pc/gpu-pod/instances/${id}/logs`, {
    params: { tailLines }
  })
}
```

### 请求/响应示例

**请求**：
```
GET /pc/gpu-pod/instances/a1b2c3d4e5f6/logs?tailLines=200
```

**响应**：
```json
{
  "code": 200,
  "msg": "success",
  "data": "2026-05-26 17:00:01 INFO Starting application...\n2026-05-26 17:00:02 INFO Loading model...\n2026-05-26 17:00:05 WARN Deprecated API usage detected\n2026-05-26 17:00:10 INFO Model loaded successfully\n..."
}
```

## 前端交互设计

### Pod 日志查看对话框

- **触发方式**：在"更多操作"菜单中点击"查看Pod日志"
- **展示内容**：
  - 日志内容区域（等宽字体，支持滚动）
  - 行数选择器（50/100/200/500/1000行）
  - 刷新按钮
  - 下载日志按钮
  - 自动刷新开关（可选）
- **样式设计**：
  - 日志内容使用深色背景，类似终端风格
  - 支持关键字高亮（ERROR/WARN/INFO等）
  - 支持自动滚动到底部

### 使用流程

1. 用户在实例列表中找到目标实例
2. 点击"更多"按钮，选择"查看Pod日志"
3. 弹出Pod日志对话框，默认加载最近100行日志
4. 用户可以：
   - 滚动查看历史日志
   - 选择加载更多行数（最大1000行）
   - 点击刷新按钮重新加载最新日志
   - 点击下载按钮将日志保存到本地
   - 开启自动刷新实时查看最新日志（可选）

## 技术实现要点

### 日志获取机制

1. **实时查询**：每次打开日志对话框或点击刷新时，实时从 GPU Pod 服务获取最新日志
2. **行数控制**：通过 `tailLines` 参数控制返回的日志行数，避免一次性返回过多数据
3. **不做本地缓存**：日志内容实时获取，不做本地缓存，确保看到的是最新日志

### 大日志处理

1. **分页加载**：对于日志量大的情况，考虑实现分页加载或滚动加载
2. **前端虚拟滚动**：对于超长的日志内容，使用虚拟滚动技术优化性能
3. **下载功能**：提供日志下载功能，方便用户查看完整的日志文件

### 实时日志（可选扩展）

如果需要实现实时日志推送功能，可以考虑：
1. WebSocket 连接 GPU Pod 服务的日志推送接口
2. Server-Sent Events (SSE) 实现服务器推送
3. 前端轮询方式（简单但实时性较差）

## 安全考虑

1. **权限控制**：只有实例的创建者才能查看该实例的日志
2. **敏感信息过滤**：日志中可能包含敏感信息，需要考虑是否进行脱敏处理
3. **访问频率限制**：限制日志查看的频率，防止恶意刷接口
4. **传输安全**：使用 HTTPS 确保日志内容在传输过程中加密

## 错误处理

| 错误场景 | 错误码 | 处理建议 |
|---------|--------|---------|
| 实例不存在 | 404 | 检查实例ID是否正确 |
| 无权访问 | 403 | 只能查看自己的实例 |
| 暂无日志 | 200 (空内容) | 实例刚创建，尚未产生日志 |
| 获取日志失败 | 500 | 联系管理员或稍后重试 |
| GPU Pod服务不可用 | 503 | 检查GPU Pod服务状态 |
