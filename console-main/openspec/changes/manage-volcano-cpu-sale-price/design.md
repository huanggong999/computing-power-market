## Context

当前火山云 GPU 已有“上游目录/价格快照 + 平台售价配置 + 服务端重新计价”的链路。独立 CPU 使用 `/api/v1/cpu/regions`、`/api/v1/cpu/instance-types` 和 `/api/v1/cpu/prices`，其中 `price` 是按量每小时价格，`priceMonthly` 是包年包月的每月价格；包年请求通过 `billingMode=yearly` 与 `duration` 表示年数，但没有独立年价。CPU 购买目前由独立适配器异步提交，创建可能持续数分钟，因此价格读取、展示和扣费必须与创建状态解耦。

## Goals / Non-Goals

**Goals:**

- 增加 CPU 原始价格与平台售价的持久化、全部地域刷新、局部失败反馈和审计信息。
- 在现有 GPU 资源管理页提供 CPU Tab，复用 GPU 的权限和价格操作模型。
- 提供独立 CPU 价格目录接口，注入启用的平台价；没有有效原价的规格从用户购买目录中隐藏。
- 服务端按当前价格重新计算用户应付金额，向火山云创建请求传原始购买参数，并保存原价、平台价、溢价、计费方式、数量、时长和价格版本快照。

**Non-Goals:**

- 不改变火山云 CPU 创建、轮询、启动、停止、释放接口的业务语义。
- 不为包年建立独立价格字段；包年始终复用包月单价，购买页不显示合计。
- 不修改既有 GPU 售价配置或 GPU 目录的价格规则。

## Decisions

### 1. 独立 CPU 价格表，复用 GPU 的双价格模型

新增 CPU 价格配置表，唯一维度为 `region + instance_type_id + billing_type`，保存 CPU 规格识别字段、上游原价、平台售价、币种、启用状态、备注和审计时间。`billing_type` 仅使用火山云接口定义的 `on_demand` 与 `monthly`；`yearly` 解析到 `monthly`。

选择独立表而不是把 CPU 行塞进 GPU 表，是因为 CPU 规格没有 GPU 型号/显存维度，且 CPU 上游目录与生命周期接口独立。平台价解析服务与 GPU 保持“启用配置优先、否则回退上游价”的语义。

### 2. 全部地域刷新采用逐地域容错 upsert

刷新接口先读取 CPU 地域列表，再逐地域调用 `/cpu/prices?refresh=true`（必要时补充规格目录），按实例规格和计费分类 upsert 原价。单地域失败不回滚成功地域，返回成功/失败地域明细并保留失败地域已有数据。刷新期间前端按钮显示 loading 并禁用重复点击。

同步规则保留已有管理员售价；新上游价高于现有售价时把售价抬到新原价并保持启用；上游价下调时不自动降低平台价。没有价格对象或价格无效的规格不注入用户目录。

### 3. 独立用户端价格目录接口

新增 `/pc/cpu-instance/prices`（或同一 CPU 模块下等价稳定路径），由服务端读取 CPU 价格快照和启用配置，返回地域、规格、`price`、`priceMonthly`、`salePrice`、`salePriceMonthly`、状态和价格版本。接口不让浏览器直连火山云，避免上游延迟和价格口径分叉。购买页在地域/规格变化时额外请求该目录，按计费方式只展示单价，不显示合计；包年使用包月单价。

### 4. 服务端价格权威与订单快照

CPU 购买提交可以携带展示价格快照，但服务端必须按地域、规格和计费方式重新读取上游快照与启用平台价，校验价格大于零后计算平台应付金额。火山云创建调用只接收原始 CPU 购买参数，不能使用浏览器传入金额。订单配置保存 upstream、sale、premium、currency、unit、billingType、quantity、duration 和 priceVersion，沿用 GPU 的订单/余额扣款字段。

### 5. 与异步创建解耦

价格校验和扣款在创建任务入队前完成；入队后继续使用已有 CPU 创建操作表和幂等请求编号。创建中、失败和请求状态未知由现有操作状态链路提示，价格功能不等待云端实例变为运行状态。

## Risks / Trade-offs

- [火山云价格接口逐地域刷新耗时或预算耗尽] → 使用逐地域容错，返回明细并保留旧快照；用户端只读本地快照。
- [上游价格下调后平台价相对变高] → 按已确认规则保留平台价，后台同时展示原价和差额供管理员调整。
- [原价上涨导致平台售价自动变化] → 在刷新结果和后台更新时间中记录自动抬价，订单保存价格版本便于追溯。
- [CPU 规格目录与价格接口短暂不一致] → 只返回具备有效原价的规格，缺价规格隐藏；后台保留原有快照直到成功同步。
- [前端价格被篡改] → 服务端重新解析价格并以服务端金额扣款，前端快照只用于留档。

## Migration Plan

1. 发布 CPU 价格表、索引和服务端价格解析接口；首次刷新全部地域建立原始快照。
2. 发布后台 CPU Tab，验证刷新汇总、售价编辑、启停和恢复默认权限。
3. 发布用户端独立价格目录请求和单价展示；无价规格默认不展示。
4. 发布 CPU 订单价格校验与双价格快照，观察对账字段和异步创建链路。
5. 若需回滚，关闭 CPU 价格目录入口并回退用户端展示；保留价格表和历史订单快照，不影响 GPU 价格链路。

## Open Questions
