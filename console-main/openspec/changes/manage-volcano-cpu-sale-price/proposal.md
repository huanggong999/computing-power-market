## Why

独立 CPU 购买页目前只能读取火山云原始目录，后台没有与 GPU 对等的价格维护、刷新和改价能力，导致用户展示价无法稳定管理，也无法在平台售价与火山云实际创建成本之间形成可追溯的订单快照。需要补齐 CPU 的价格目录和后台管理链路，并复用 GPU 的服务端计价边界。

## What Changes

- 新增火山云 CPU 原始价格快照与平台售价配置，维度为地域、CPU 实例规格和接口定义的计费分类；按量/小时与包月价格直接对应火山云目录，包年购买复用包月单价。
- 在现有火山云资源管理页增加 CPU Tab，沿用 GPU 的查询、编辑、启停、恢复默认和权限模型；支持一次刷新全部地域，成功地域入库，失败地域返回明细并保留旧数据。
- 刷新时自动 upsert 火山云原价，保留管理员平台售价；新原价上涨超过平台售价时自动抬高平台售价并保持启用，原价下调不自动降低平台售价。
- 新增独立 CPU 价格目录接口，用户购买页额外请求该接口；有启用平台售价时展示平台价，否则回退火山原价；没有有效价格的规格隐藏且不可购买。
- CPU 购买页只展示当前计费方式的单价，不显示合计；包年只展示复用的包月单价。
- CPU 下单沿用 GPU 的价格边界：平台价用于用户应付金额，火山云原价用于实际创建参数，服务端重新解析价格并保存双价格快照，前端传入的展示金额不作为扣款依据。

## Capabilities

### New Capabilities

- `volcano-cpu-sale-price-management`: 火山云 CPU 原始价格同步、平台售价维护、目录注入、用户端展示和订单双价格快照。

### Modified Capabilities

- 无。现有 GPU 售价管理需求保持不变，CPU 价格能力作为独立能力新增。

## Impact

- `console-main`：新增 CPU 价格实体、迁移、Mapper/Service、目录与价格控制器接口，并扩展 CPU 适配客户端以读取火山云区域、规格和价格数据。
- `ux-admin-main`：扩展火山云 GPU 资源管理页的 CPU Tab、全部地域刷新反馈、价格编辑和状态操作。
- `ux-user-main`：CPU 购买页新增独立价格目录请求、平台价显示、无价规格过滤和价格快照字段传递。
- 订单与余额扣款：新增 CPU 价格解析和双价格快照，保持火山云成本参数与平台应付金额分离。
- 数据库：新增 CPU 价格配置表及必要的目录快照结构，不修改既有 GPU 价格表数据。
