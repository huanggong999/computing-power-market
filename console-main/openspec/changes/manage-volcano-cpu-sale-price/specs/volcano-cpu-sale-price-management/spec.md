## ADDED Requirements

### Requirement: CPU 原始价格与平台售价配置
系统 MUST 按地域、CPU 实例规格和火山云计费分类保存 CPU 原始价与平台售价。按量/小时和包月分别维护；包年 MUST 解析并使用包月价格。平台售价启用时必须不低于对应火山云原价。

#### Scenario: 保存有效 CPU 平台售价
- **WHEN** 管理员为地域、实例规格和按量或包月计费分类保存不低于原价的售价
- **THEN** 系统 MUST upsert 唯一价格配置并立即用于后续新目录、试算和购买

#### Scenario: 拒绝低于原价的售价
- **WHEN** 管理员提交低于当前火山云原价的 CPU 平台售价
- **THEN** 系统 MUST 拒绝保存并返回包含原价约束的校验错误

#### Scenario: 包年价格解析
- **WHEN** 用户选择 `billingMode=yearly`
- **THEN** 系统 MUST 使用该规格启用的包月平台价或包月原价，且不得要求独立包年价格记录

### Requirement: 全部地域 CPU 价格刷新
系统 MUST 支持一次刷新全部 CPU 地域，逐地域读取火山云价格并自动 upsert 原价。成功地域 MUST 入库；失败地域 MUST 返回明细并保留旧数据。已有平台售价 MUST 保留；新原价上涨超过平台售价时平台售价 MUST 自动抬高并保持启用，原价下调时平台售价 MUST 不自动降低。

#### Scenario: 全部地域刷新成功
- **WHEN** 管理员触发全部地域刷新且所有地域价格接口成功
- **THEN** 系统 MUST 返回成功地域汇总、更新时间和入库数量，并更新原始价格

#### Scenario: 部分地域刷新失败
- **WHEN** 某些地域价格接口失败而其他地域成功
- **THEN** 系统 MUST 提交成功地域数据，返回成功/失败地域明细，并保留失败地域旧快照

#### Scenario: 原价上涨自动抬价
- **WHEN** 刷新得到的新原价高于已启用的平台售价
- **THEN** 系统 MUST 将平台售价抬高到新原价并保持启用

#### Scenario: 原价下调保留平台价
- **WHEN** 刷新得到的新原价低于当前平台售价
- **THEN** 系统 MUST 保留当前平台售价，不得自动下调

### Requirement: CPU 后台价格管理页
系统 MUST 在现有火山云 GPU 资源管理页提供 CPU Tab，并沿用 GPU 页面的权限、查询、价格编辑、启停和恢复默认操作。刷新按钮在执行期间 MUST 显示 loading 并禁止重复触发，完成后 MUST 展示刷新汇总。

#### Scenario: 管理员查看 CPU 价格
- **WHEN** 管理员打开 CPU Tab
- **THEN** 系统 MUST 展示地域、CPU 规格、火山云原价、平台售价、差额、计费分类、启用状态和更新时间

#### Scenario: 停用并恢复默认
- **WHEN** 管理员停用或恢复某条 CPU 平台售价
- **THEN** 官网目录和新购买 MUST 回退使用对应火山云原价

### Requirement: 独立 CPU 价格目录
系统 MUST 提供独立的用户端 CPU 价格目录接口，由服务端返回有效原价和解析后的平台价。启用平台售价存在时 MUST 返回平台价；没有启用配置时 MUST 回退原价；原价缺失、无效或价格状态不可用的规格 MUST 不返回。

#### Scenario: 返回平台价
- **WHEN** 用户请求某地域 CPU 价格目录且规格存在启用售价
- **THEN** 系统 MUST 返回火山云原价字段和平台售价字段，且平台售价用于页面展示

#### Scenario: 缺省回退原价
- **WHEN** 用户请求的规格没有启用售价配置
- **THEN** 系统 MUST 返回原价作为展示价

#### Scenario: 隐藏无价规格
- **WHEN** CPU 规格没有有效按量或包月原价
- **THEN** 系统 MUST 从用户端目录中隐藏该规格并禁止购买

### Requirement: CPU 购买页单价展示
CPU 购买页 MUST 额外请求独立价格目录，按当前计费方式展示单价，不显示购买合计。包年 MUST 只展示复用的包月单价。

#### Scenario: 切换计费方式
- **WHEN** 用户切换按量、包月或包年
- **THEN** 页面 MUST 重新选择对应展示单价，包年使用包月单价，且不显示合计

### Requirement: CPU 服务端计价与实际创建
系统 MUST 在 CPU 购买提交前重新读取服务端价格并计算平台应付金额。平台价 MUST 用于用户应付金额和余额扣款；火山云原价 MUST 用于实际创建请求的价格相关参数。浏览器传入的金额或价格快照 MUST NOT 决定扣款。

#### Scenario: 服务端价格有效
- **WHEN** 用户提交有效 CPU 购买参数且服务端找到有效原价与平台价
- **THEN** 系统 MUST 按平台价计算应付金额、完成余额校验并将原始购买参数提交到创建队列

#### Scenario: 服务端价格缺失或变化
- **WHEN** 提交时服务端找不到规格价格或价格不大于零
- **THEN** 系统 MUST 拒绝入队并返回价格不可用或已变化提示

### Requirement: CPU 订单双价格快照
CPU 订单 MUST 保存火山云原价、平台售价、单位溢价、总溢价、币种、计费单位、计费分类、数量、时长和价格版本。已提交订单的价格 MUST 不因后续后台改价而变化。

#### Scenario: 创建成功保存快照
- **WHEN** CPU 创建任务入队并完成订单记录
- **THEN** 订单配置 MUST 保存完整双价格快照，订单应付金额 MUST 等于平台价乘以数量和计费时长

#### Scenario: 后台改价不影响已提交订单
- **WHEN** 管理员在订单提交后修改或停用售价
- **THEN** 已提交订单的应付金额和价格快照 MUST 保持原值，新购买使用新配置
